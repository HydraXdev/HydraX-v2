## 🔌 ZMQ Architecture Overview

**BITTEN v2.0 uses 5 ZMQ ports:**

| Port | Type | Direction | Purpose | Bind Side | Connect Side |
|------|------|-----------|---------|-----------|--------------|
| 5555 | ROUTER/DEALER | Bidirectional | Fire commands | zmq_gateway | EA (MT5) |
| 5556 | PULL | EA→Server | Market data ingestion | zmq_gateway | EA (MT5) |
| 5557 | PUB/SUB | Server→Clients | Signal publication | signal_engine | Consumers |
| 5558 | PULL | EA→Server | Trade confirmations | zmq_gateway | EA (MT5) |
| 5560 | PUB/SUB | Server→Clients | Market data broadcast | zmq_gateway | Consumers |

**Critical Dependencies:**
- zmq_gateway MUST bind ports 5555, 5556, 5558, 5560 before other services start
- signal_engine binds port 5557 independently
- EA connects to 5555 (DEALER), pushes to 5556 and 5558
- All server services connect to 5557 and 5560 for data consumption

## 🚨 Common ZMQ Connection Issues

### Issue 1: "Address Already in Use" Error

**Symptoms:**
```
zmq.error.ZMQError: Address already in use
```

**Root Cause**: Another process is bound to the port

**Diagnosis**:
```bash
# Find which process owns the port
lsof -i:5555
lsof -i:5556
lsof -i:5557
lsof -i:5558
lsof -i:5560

# Alternative: Check with netstat
ss -tulpen | grep -E ":(5555|5556|5557|5558|5560)"
```

**Resolution**:
```bash
# Option 1: Kill the blocking process
kill -9 $(lsof -ti:5555)
kill -9 $(lsof -ti:5556)
kill -9 $(lsof -ti:5557)
kill -9 $(lsof -ti:5558)
kill -9 $(lsof -ti:5560)

# Option 2: Restart the service cleanly
pm2 restart zmq_gateway
pm2 restart signal_engine

# Wait for port bindings
sleep 3

# Verify ports bound
ss -tulpen | grep -E ":(5555|5556|5557|5558|5560)"
```

**Prevention**: Always use `pm2 stop` or `pm2 restart` instead of `kill -9`

### Issue 2: EA Not Connecting to Port 5555

**Symptoms:**
- EA logs show "Connection refused"
- No heartbeat messages appearing in zmq_gateway logs
- `ea_instances` table shows `last_seen` > 120 seconds ago

**Root Cause**: zmq_gateway not running or port 5555 not bound

**Diagnosis**:
```bash
# Check if zmq_gateway is running
pm2 list | grep zmq_gateway

# Check port 5555 binding
ss -tulpen | grep :5555

# Check zmq_gateway logs
pm2 logs zmq_gateway --lines 50 | grep "ROUTER bound"
```

**Resolution**:
```bash
# Restart zmq_gateway
pm2 restart zmq_gateway

# Wait for binding
sleep 3

# Verify port bound
ss -tulpen | grep :5555

# Expected output: :::5555 LISTEN
```

**EA-Side Actions** (if server is healthy):
```
1. EA will auto-reconnect every 5 seconds
2. Check MT5 Expert Advisor logs for connection attempts
3. If EA shows "Connected successfully", wait 30 seconds for heartbeat
4. If still no connection after 2 minutes, restart EA in MT5
```

**Database Verification**:
```bash
# Check EA last seen timestamp
sqlite3 /root/HydraX-v2/bitten.db "SELECT target_uuid, user_id, datetime(last_seen, 'unixepoch') as last_seen_time, (strftime('%s','now') - last_seen) as age_seconds FROM ea_instances WHERE target_uuid = 'COMMANDER_DEV_001';"
```

**Success Criteria**: `age_seconds` < 30

### Issue 3: Signal Publication Failure (Port 5557)

**Symptoms:**
- Signals generated by signal_engine but not received by consumers
- `signals` table has new entries but no Telegram alerts
- Event bus not receiving signal events

**Root Cause**: signal_engine not bound to port 5557 or subscribers not connected

**Diagnosis**:
```bash
# Check signal_engine status
pm2 list | grep signal_engine

# Check port 5557
ss -tulpen | grep :5557

# Check recent signals
PGPASSWORD='bitten_secure_2025' psql -h localhost -p 5433 -U bitten_admin -d bitten_v2 -c "SELECT signal_id, symbol, created_at FROM signals WHERE created_at > NOW() - INTERVAL '10 minutes' ORDER BY created_at DESC LIMIT 5;"

# Test subscription
python3 <<EOF
import zmq
import time

context = zmq.Context()
subscriber = context.socket(zmq.SUB)
subscriber.connect("tcp://localhost:5557")
subscriber.setsockopt_string(zmq.SUBSCRIBE, "")
subscriber.setsockopt(zmq.RCVTIMEO, 5000)

try:
    msg = subscriber.recv_string()
    print(f"✅ Signal received: {msg[:100]}")
except zmq.Again:
    print("❌ No signals received in 5 seconds")
finally:
    subscriber.close()
    context.term()
EOF
```

**Resolution**:
```bash
# Restart signal_engine
pm2 restart signal_engine

# Wait for initialization
sleep 5

# Verify pattern detectors loaded
pm2 logs signal_engine --lines 20 | grep "Pattern detectors loaded"

# Restart consumers if needed
pm2 restart api_server
pm2 restart analytics_worker
```

### Issue 4: Confirmation Messages Not Received (Port 5558)

**Symptoms:**
- Fires created with status "PENDING" never update to "FILLED"
- `fires` table missing ticket and price data
- EA logs show trades executed but server shows no confirmations

**Root Cause**: zmq_gateway not listening on port 5558 or EA not pushing confirmations

**Diagnosis**:
```bash
# Check port 5558 binding
ss -tulpen | grep :5558

# Check zmq_gateway logs for confirmation events
pm2 logs zmq_gateway --lines 50 | grep "position_opened"

# Check recent fires
PGPASSWORD='bitten_secure_2025' psql -h localhost -p 5433 -U bitten_admin -d bitten_v2 -c "SELECT fire_id, status, ticket, price FROM fires WHERE created_at > NOW() - INTERVAL '1 hour' ORDER BY created_at DESC LIMIT 10;"
```

**Resolution**:
```bash
# Restart zmq_gateway (handles port 5558)
pm2 restart zmq_gateway

# Wait for binding
sleep 3

# Verify port bound
ss -tulpen | grep :5558

# Test confirmation flow with EA
# (Execute a small test trade via /fire command)
```

**EA-Side Verification**:
- EA should send `position_opened` events immediately after trade execution
- Check EA logs for "Confirmation sent to port 5558"
- If EA not sending, recompile EA with latest v3.005 code

### Issue 5: Market Data Not Flowing (Ports 5556, 5560)

**Symptoms:**
- No tick data appearing in logs
- signal_engine not generating signals despite active market
- Candle builders showing stale data

**Root Cause**: Telemetry bridge (zmq_gateway) not receiving from EA or not publishing

**Diagnosis**:
```bash
# Check EA sending market data
pm2 logs zmq_gateway --lines 20 | grep "tick.*EURUSD"

# Check port 5556 (EA → Server)
ss -tulpen | grep :5556

# Check port 5560 (Server → Clients)
ss -tulpen | grep :5560

# Test market data subscription
python3 <<EOF
import zmq
import time

context = zmq.Context()
subscriber = context.socket(zmq.SUB)
subscriber.connect("tcp://localhost:5560")
subscriber.setsockopt_string(zmq.SUBSCRIBE, "")
subscriber.setsockopt(zmq.RCVTIMEO, 10000)

try:
    msg = subscriber.recv_string()
    print(f"✅ Market data received: {msg[:100]}")
except zmq.Again:
    print("❌ No market data in 10 seconds")
finally:
    subscriber.close()
    context.term()
EOF
```

**Resolution**:
```bash
# Restart zmq_gateway
pm2 restart zmq_gateway

# Wait for bindings

# Verify both ports
```

## 🔄 Complete ZMQ Service Restart Sequence

**Use this when multiple ZMQ issues occur or after major changes:**

```bash
#!/bin/bash
# Complete ZMQ service restart with proper ordering

echo "=== BITTEN v2.0 ZMQ Service Restart ==="
echo "Stopping all services..."

# Stop all consumers first
pm2 stop api_server
pm2 stop analytics_worker
pm2 stop fire_service
pm2 stop signal_engine

echo "Stopping ZMQ gateway (core infrastructure)..."
pm2 stop zmq_gateway

# Wait for port release
echo "Waiting for ports to release..."
sleep 5

# Verify ports released
for port in 5555 5556 5557 5558 5560; do
    if lsof -i:$port > /dev/null 2>&1; then
        echo "⚠️  Port $port still bound, force killing..."
        lsof -ti:$port | xargs kill -9
    fi
done

echo "Starting services in correct order..."

# 1. Start core ZMQ gateway first
pm2 start zmq_gateway
sleep 3

# Verify ports bound
PORTS_OK=true
for port in 5555 5556 5558 5560; do
    if ! ss -tulpen | grep -q ":$port"; then
        echo "❌ Port $port not bound!"
        PORTS_OK=false
    fi
done

if [ "$PORTS_OK" = false ]; then
    echo "❌ ZMQ gateway failed to bind all ports. Aborting."
    exit 1
fi

echo "✅ ZMQ gateway ports bound successfully"

# 2. Start signal_engine (binds 5557)
pm2 start signal_engine
sleep 3

if ! ss -tulpen | grep -q ":5557"; then
    echo "❌ Signal engine failed to bind port 5557. Aborting."
    exit 1
fi

echo "✅ Signal engine port 5557 bound"

# 3. Start consumers (connect to 5557, 5560)
pm2 start fire_service
pm2 start api_server
pm2 start analytics_worker

sleep 2

# Verify all services online
pm2 list

echo "=== Restart Complete ==="
echo "Verify EA connection: Check ea_instances last_seen timestamp"
echo "Expected: < 60 seconds"
```

**Save as**: `/root/HydraX-v2/scripts/restart_zmq_services.sh`

## 🧪 ZMQ Connection Testing Scripts

### Test 1: Heartbeat Monitor
```python
#!/usr/bin/env python3
"""Monitor EA heartbeats on port 5556"""
import zmq
import time

context = zmq.Context()
subscriber = context.socket(zmq.SUB)
subscriber.connect("tcp://localhost:5556")
subscriber.setsockopt_string(zmq.SUBSCRIBE, "")
subscriber.setsockopt(zmq.RCVTIMEO, 30000)

print("Monitoring EA heartbeats (Ctrl+C to exit)...")
heartbeat_count = 0

try:
    while True:
        try:
            msg = subscriber.recv_string()
            if "heartbeat" in msg:
                heartbeat_count += 1
                print(f"[{time.strftime('%H:%M:%S')}] Heartbeat #{heartbeat_count}: {msg[:80]}")
        except zmq.Again:
            print("⚠️  No heartbeat received in 30 seconds")
except KeyboardInterrupt:
    print(f"\nTotal heartbeats: {heartbeat_count}")
finally:
    subscriber.close()
    context.term()
```

### Test 2: Fire Command Sender
```python
#!/usr/bin/env python3
"""Test fire command routing via port 5555"""
import zmq
import json
from collections import OrderedDict
import time

context = zmq.Context()
dealer = context.socket(zmq.DEALER)
dealer.setsockopt_string(zmq.IDENTITY, "TEST_CLIENT")
dealer.connect("tcp://localhost:5555")

# Send test fire command
fire_cmd = OrderedDict([
    ('type', 'fire'),
    ('target_uuid', 'COMMANDER_DEV_001'),
    ('fire_id', f'TEST_FIRE_{int(time.time())}'),
    ('symbol', 'EURUSD'),
    ('direction', 'BUY'),
    ('entry', 1.1000),
    ('sl', 1.0980),
    ('tp', 1.1030),
    ('lot', 0.01)
])

dealer.send_string(json.dumps(fire_cmd))
print(f"✅ Fire command sent: {fire_cmd['fire_id']}")

# Wait for response
dealer.setsockopt(zmq.RCVTIMEO, 10000)
try:
    response = dealer.recv_string()
    print(f"✅ Response received: {response}")
except zmq.Again:
    print("❌ No response in 10 seconds")
finally:
    dealer.close()
    context.term()
```

## 📊 ZMQ Health Monitoring

**Add to cron for automated monitoring:**
```bash
# Check every 5 minutes
*/5 * * * * /root/HydraX-v2/scripts/zmq_health_check.sh >> /var/log/zmq_health.log 2>&1
```

**Script**: `/root/HydraX-v2/scripts/zmq_health_check.sh`
```bash
#!/bin/bash
TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
ERRORS=0

# Check all ports
for PORT in 5555 5556 5557 5558 5560; do
    if ! ss -tulpen | grep -q ":$PORT"; then
        echo "[$TIMESTAMP] ❌ Port $PORT not bound"
        ERRORS=$((ERRORS + 1))
    fi
done

# Check EA last seen
AGE=$(sqlite3 /root/HydraX-v2/bitten.db "SELECT (strftime('%s','now') - last_seen) FROM ea_instances WHERE target_uuid = 'COMMANDER_DEV_001';" 2>/dev/null)

if [ -z "$AGE" ] || [ "$AGE" -gt 120 ]; then
    echo "[$TIMESTAMP] ❌ EA heartbeat stale ($AGE seconds)"
    ERRORS=$((ERRORS + 1))
fi

if [ $ERRORS -eq 0 ]; then
    echo "[$TIMESTAMP] ✅ All ZMQ ports healthy, EA connected"
else
    echo "[$TIMESTAMP] ⚠️  $ERRORS issue(s) detected"
    # Send alert (implement notification here)
fi
```

## 📞 Escalation Path

**If ZMQ issues persist after all troubleshooting:**

1. **Collect diagnostic data**:
   ```bash
   pm2 logs zmq_gateway --lines 200 > zmq_gateway_logs.txt
   pm2 logs signal_engine --lines 200 > signal_engine_logs.txt
   ss -tulpen | grep -E ":(5555|5556|5557|5558|5560)" > port_bindings.txt
   ```

2. **Create support package**:
   ```bash
   tar -czf zmq_diagnostics_$(date +%Y%m%d_%H%M%S).tar.gz \
       zmq_gateway_logs.txt \
       signal_engine_logs.txt \
       port_bindings.txt \
       /root/HydraX-v2/.env
   ```

3. **Contact Infrastructure Team** with diagnostic package
